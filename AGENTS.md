# Repository Guidelines

## Project

Kwal — KDE Plasma utility to manage the wallpaper and tint applications/tools with palettes extracted from the wallpaper. C++/Qt6/QML rewrite of the Python original (sibling repo `../Kwal` — read its AGENTS.md for feature spec). App ID: `org.kde.kwal`.

## Development Directives

- **Simplicity first.** The rewrite keeps the new project as simple and clean as possible: smallest code that does the job, no speculative abstractions, no legacy quirks.
- **No legacy features by default.** The old app included: wallpaper management (folders, thumbnails, filters, video/SVG support), palette extraction (Material You / Color Thief / wal), tool tinting (Fastfetch, Starship, Ulauncher), custom commands, live preview with shaders. **Before implementing any of these, ask the user which ones to keep** — never port unasked. Approved and implemented so far: wallpaper management (folders, thumbnails, videos in the grid), palette extraction (Material You via the official mcu library + ImageMagick), and custom commands (placeholders + execution on wallpaper apply; configured in the wallpaper detail drawer) — the consolidated plan is `PLAN_WALLPAPERS_CONSOLIDADO.md`; everything else still needs asking.
- **Standards over precedent.** Follow KDE HIG + Kirigami skills + current Qt best practices. Where the old app did something differently (threading, file watching, config format), the new code follows current standards — the old implementation is a feature reference, not a pattern reference.
- **Minimal dependencies.** System packages only; no new third-party library without explicit user approval. Approved exceptions (2026-10-22): CMake `FetchContent` for `tomlplusplus` (v3.4.0) and `material-color-utilities` (pinned commit `bd811e4ca2ab94c4ce3cadc89c19b1820b9704b3`, built as static lib `mcu_lib`; the checked-out tree is patched once in CMake so it builds standalone on GCC 16 without abseil).

## Stack (exact versions on this system)

- Qt 6.12.0 (system packages, pkg-config + CMake)
- Kirigami 6.31.0 / KDE Frameworks 6.31 (`KF6::Kirigami`, `KF6::ConfigCore`)
- CMake 4.x + Ninja, GCC 16
- **Qt5/Qt6 coexist:** `/usr/bin/qml` and `/usr/bin/qmllint` are **Qt 5.15**. Use `qml6` and `/usr/lib/qt6/bin/qmllint` (or the app binary directly).
- **Image-format plugins are separate packages on Arch and nothing depends on them:** QtGui itself decodes png/bmp/xpm, `qt6-base` ships the jpeg/gif/ico handlers, **`qt6-imageformats`** ships `libqwebp/libqtiff/libqicns/libqtga/libqwbmp`, and **`qt6-svg`** ships `libqsvg.so`. The grid's accepted extensions (`wallpapermodel.cpp`: png, jpg, jpeg, webp, bmp, gif, svg) therefore need all three, so CI, the AppImage workflow and `packaging/aur/PKGBUILD` install them explicitly. Without a handler `QImageReader` reports "Unsupported image format" (`imageCount()` = -1), which silently reads as "static, no categories, no palette". `kimageformats` (avif/heif/jxl/jp2) is deliberately **not** a dependency: the model does not accept those extensions.

## Commands

```sh
./build.sh             # helper: [build|test|run|config|clean], auto-configures on first run
cmake --preset default     # configure (Ninja, Debug, compile_commands.json)
cmake --build --preset default
ctest --test-dir build     # run tests (QtTest + CTest)
./build/kwal               # run (or via kwin MCP for headless UI verification)
```

Tests sandbox the user dirs: `tst_appcontroller` sets `HOME`/`XDG_*` to a temp dir *before* constructing `QCoreApplication` so KConfig and QStandardPaths never touch the real home. New tests must keep this.
## Build assurance (mandatory)

- **Clean build is the only proof.** Never declare a build healthy from an incremental compile on a stale tree: configure warnings and compiler warnings only surface on a fresh configure + full recompile. Verification = `./build.sh clean` → `cmake --preset default` → `cmake --build --preset default` → **zero errors, zero warnings** → `ctest`.
- **Never filter or truncate build output** (`tail`, `grep` on the log) when verifying — a filtered log is not a verification; read the full output.
- **Zero-warning policy.** Every compiler, AutoMoc, and CMake warning must be fixed at the source — no suppressions, no pragmas, no "pre-existing" excuses. A warning found while working (even in code you did not touch) is fixed in the same task.

## Working method (mandatory)

- **Evidence before claims.** Never assert how code or tooling behaves from memory or general knowledge — read the installed headers/packages/sources that actually govern the behavior. The installed file is the proof.
- **Root cause, not symptom.** When an error or warning appears, identify its cause (read the relevant file) before fixing it. Silencing, suppressing, or special-casing without understanding the cause is forbidden.
- **Full output is the proof.** Verification means reading the complete unfiltered output (see Build assurance), not a filtered count.
- **Honest reporting.** Report what was done and what is proven; state explicitly what is unverified. Never hide, gloss over, or blame the user/environment without evidence.
- **An alive process is not a loaded UI.** A running PID is not proof the window exists. When the window fails to appear, the first diagnostic is the app's own stdout/stderr: QML load failures print there (`Cannot assign to non-existent property "onX"`, `Type <X> unavailable` → `Component unavailable`). A missing window is a QML load failure to investigate before the session or environment is suspected. That channel only works because `main.cpp` re-installs its own message handler **after** the application object exists: `QtWebEngineQuick::initialize()` installs one that forwards Qt logging into Chromium's logging system, and the last installer wins — without the re-install every `qWarning` (including the QML load failures above) disappears without a trace. QML `console.log/info/warn/error` prints nothing on this Arch Qt build at all; drive runtime diagnostics from C++ (`qWarning`) or from a screenshot.

## Tooling rules (mandatory)

1. **Skills first:** read the relevant skill before writing code (`qt-qml`, `qt-cmake-project`, `Kirigami`). Follow them.
2. **Installed module is the source of truth, not memory or master docs.** Before using any QML type/property from any module (Kirigami, Qt, third-party), verify it exists in **this** build:
   - QML types/properties: `grep` the module's `plugins.qmltypes`/`qmldir` under `/usr/lib/qt6/qml/` (e.g. `org/kde/kirigami/…`, `org/qtquick/webengine/plugins.qmltypes`) or the `.qml` sources. Never from memory of another Qt version — this Qt 6.12 `QQuickWebEngineView` has no `loadFinished` signal (older Qt did); the load-completed equivalent is `loading`/`loadingChanged`.
   - LSP: `xd://lsp` diagnostics/hover on the file (clangd + qmlls6 configured in `.omp/lsp.json`).
   - Docs: `qt_documentation_search` MCP (Qt 6.12) for Qt APIs; api.kde.org / develop.kde.org for Kirigami.
3. **LSP is the priority tool** (clangd + qmlls6, configured in `.omp/lsp.json`) for both code intelligence and quality:
   - Code intelligence (definitions, references, hovers, renames) MUST use `xd://lsp`, never raw text search; cross-file renames only via LSP `rename`/`rename_file`.
   - After every edit of a `.cpp`/`.h`/`.qml` file: run `xd://lsp` `diagnostics` on it (per-file; workspace-wide `file:"*"` fails — project type not detected) and fix every diagnostic before calling the file done. **There is no minor warning**: a diagnostic — warning or error; qmllint's `no matching signal found for handler` is a hard defect, not a nit — is resolved in the same pass or proven a false positive against the installed module. A green build never outranks an unresolved diagnostic.
   - LSP complements the compiler — it catches what GCC misses (e.g. unused includes). A file is only clean when **both** the compiler and LSP report zero diagnostics.
4. **Verify UI empirically:** kwin MCP — `session_start`, then `launch_app` with `command:` (session_start does not launch the app), `screenshot` + `window_geometry`, then `session_stop`. Screenshots are the proof. The QML cache compiles fine even with a handler for a signal that does not exist; the failure surfaces only at runtime and takes down the whole component hierarchy from a single broken file. A green build is a weaker guarantee for `.qml` than for C++: any edit touching handlers/properties must be loaded live and the window confirmed. Without a kwin session, the same proof comes from `QT_QPA_PLATFORM=offscreen` plus a temporary C++ hook that grabs the window (`QQuickWindow::grabWindow()` returns a `QImage` in this Qt) and saves it — drive the state under test from a sandboxed `HOME`/`XDG_*`, seeding the config at the file `AppController::configFilePath()` reports (`$XDG_CONFIG_HOME/kwalrc`); a seed written anywhere else is simply never read and every setting falls back to its default.
5. **Session hygiene (kwin MCP) — mandatory.** The isolated session runs a full KWin compositor and consumes real GPU/CPU resources. Exactly **one** active session at a time: `session_start` → verify → `session_stop` immediately, in the same step. Never leave a session running between unrelated steps, while editing code, or while waiting on other work — abandoned sessions accumulate and starve the machine (observed: stale sessions + abandoned app instances made the app and the compositor stop responding). Before a new `session_start`, check for leftovers and clean them: `ps -eo pid,cmd | grep 'kwin_wayland --virtual'` (kill stray PIDs) and `launch_app`ed apps that are no longer needed (kill by the PID `launch_app` returned). If `session_start` or the app misbehaves and a session was just stopped, suspect leaked resources before suspecting the code.
6. Do not assume APIs from other Kirigami versions. If a pattern is not verifiable locally, say so instead of guessing.
7. **The standard chain is the path to success: LSP → clean build → tests → live UI.** When observed behavior contradicts expectations, diagnose with the tools in that order: `xd://lsp` hover/definition on the exact line (resolved type and resolved overload — never an assumption), then `./build.sh clean` + build + `ctest`, then kwin screenshot. Manual probe binaries, replica TUs, and speculative experiments are rabbit holes: at most one diagnostic cycle before returning to the standard chain — they must never replace it.

## Architecture

- Single executable `kwal` + QML module `org.kde.kwal`; `main.cpp` loads `Main` via `loadFromModule`. On KDE desktops it sets `QT_QPA_PLATFORMTHEME=kde` and `QT_QUICK_CONTROLS_STYLE=org.kde.desktop` (never overriding explicit user settings).
- Build sharing: two `OBJECT` libraries compile the non-QML sources once instead of re-listing them per target. `kwal_core` = `colorcategory` + `tools/fileutil` only (self-contained; linked by the app, `kwal-transition` and every test). `kwal_plasma` = `plasmaapply` alone — it calls `WallpapersInfo` (which is a `QML_SINGLETON` and therefore MUST stay compiled inside each consuming target or the module registration drops it), so `kwal_plasma` is linked only by the targets that both need PlasmaApply's symbols and compile `wallpapersinfo.cpp`: `kwal`, `kwal-transition`, `tst_transitions`, `tst_appcontroller`, `tst_plasmaapply` (the first four also link `kwal_transitions`, whose `planes.cpp` uses `plasmaapply::Ini`). `wallpapersinfo`/`wallpapermodel` are `QML_SINGLETON`/`QML_ELEMENT` and are never moved into a shared lib for the same registration reason; each target compiles them individually.
- `AppController` (`QML_ELEMENT`, instantiated in `Main.qml`) is the app state/services: folders, wallpaper selection, config, and applying the wallpaper through `PlasmaApply`.
- Custom commands: `AppController` owns the list (CRUD slots `addCustomCommand`/`updateCustomCommand`/`setCustomCommandEnabled`/`removeCustomCommand`/`moveCustomCommand` over the `[Commands]` KConfig group, compact JSON of `{command, enabled}`) and `selectedSourceColorIndex` (0-based; default 0 = first matugen dot; **per wallpaper in-session** — the in-memory selection map is restored on every wallpaper change, but **only the applied wallpaper's selection is persisted**: dot clicks on other wallpapers are session-local, and `setCurrentWallpaper` makes the selection active at apply time the stored one; the config holds a single entry in `sourceColorSelections` in `[Wallpapers]`; drives the dot highlight in grid and drawer). Placeholders `%path%` (wallpaper path), `%image%` (image actually applied — the cached first frame for videos), `%scolor%` (hex of the selected matugen dot; `%sc%` is the short form), `%mode%` (dark/light) and `%ccolor%` (custom color) are expanded by `AppController::expandPlaceholders`; the enabled non-empty commands are joined with `&&` and run **last** in the apply pipeline — `AppController::runCustomCommands` after the `PlasmaApply` result in the apply job, detached `sh -c` via `QProcess::startDetached`, failures emit a notification. The drawer mirrors the list in a local `ListModel` (rebuilt from `app.customCommands` on load) so the rows are drag-reorderable with `Kirigami.ListItemDragHandle` + `ListModel.move()`; each edit updates both the mirror and the app's slot.
- `PlasmaApply` (`src/plasmaapply.{h,cpp}`, owned by `AppController`; `applyWallpaper` runs on a QThreadPool so a slow shell never blocks the UI): routes images to `org.kde.image` and videos to `luisbocanegra.smart.video.wallpaper.reborn` when installed (checked in the user and system Plasma wallpaper directories), falling back to the cached first frame applied as an image when the plugin is absent (no frame → failure with a message). Each desktop is updated per-desktop via D-Bus `org.kde.PlasmaShell` → `setWallpaper` (desktop ids from a `desktops()` shell script via `evaluateScript`, falling back to parsing the `plasma-org.kde.plasma.desktop-appletsrc` sections), with a byte-preserving linear INI editor writing the same sections into appletsrc when D-Bus is unavailable or a desktop fails. The optional lockscreen switch mirrors the applied wallpaper into `kscreenlockerrc` (`[Greeter] WallpaperPlugin=<plugin>` + `[Greeter][Wallpaper][<plugin>][General]`: `Image=fileUrl` for images, `VideoUrls`/`LastVideo`/`LastVideoPosition=0` for video — one background for all screens). Video playlists are computed by `plasmaapply::computeVideoUrls` (target enabled, every other entry disabled, entry order preserved, fields emitted in the plugin page's own JSON.stringify field order so the stored string round-trips byte-identically); the playlist entry and `LastVideo` keep the raw `file://` path (raw UTF-8 and spaces), the same form the plugin's own config page writes (its `QUrl::toString` with PreferredEncoding — percent-encoding them breaks the page's display and exact-string `LastVideo` match). `clearAllResizes()` (the Settings "Clear resizes cache" button, `edit-clear`) deletes every cached copy referenced by an entry's `resized`, clears those fields, saves the index and emits `purged()` (which prunes the dead URLs from the desktop `appletsrc`); a no-op while a batch is running. `clearAllTags()` (the "Clear all tags" `edit-clear` button) empties `tags` on every entry, clears `tags_manual`, saves and emits `entryChanged` per affected file. Dead playlist URLs are pruned by `pruneVideoUrls` (pure: drops `VideoUrls` entries whose `file://` URL points to a deleted local file, keeps the rest byte-identical) and `pruneDeadVideoUrls()` (applies it to every section of the desktop `appletsrc` with a `VideoUrls` via the linear editor, writes only when changed) — run at startup and after every `WallpapersInfo::purged`.
- Wallpaper transitions (consolidated plan: `KWAL_TRANSICIONES_PLAN.md`): with `transitionEnabled`, `AppController::setWallpaper` runs the standalone binary `kwal-transition` (`src/kwal-transition.cpp`, found next to the app or on `PATH`) from the apply job via `QProcess`; without the binary it degrades to the direct `PlasmaApply` path. The binary (`src/transitions/`: C++ port of the awww/kdewall reference `../kdewall-plugin-switcher`) opens a full-screen `zwlr_layer_shell_v1` overlay per output at the configured layer (memfd double buffering, frames paced by compositor frame callbacks, so the effective duration is duration + compositor stalls), painting the **incoming** image (Cover) or the **outgoing** planes (Reveal, videos with the reborn plugin only when every target desktop is an image), animates to the exact end state, performs the Plasma switch (the same per-desktop `setWallpaper` D-Bus / appletsrc path as `PlasmaApply`) and holds the overlay until the new wallpaper has loaded (1500 ms video / 400 ms image — the reference's hold constants) before tearing down; any setup failure degrades to a plain switch. The app mirrors the lockscreen itself after the binary exits 0. Without `transitionAdvanced` the binary applies per-type presets (duration 0.9 s, bezier `.54,0,.34,.99`, …) and ignores the stored advanced values (the reference's `resolve` rule). The Wallpapers settings page has a Transitions section (enable switch, layer, preset type, and the advanced group: duration/fps/step/angle/pos/invert-y/bezier/wave).
- `WallpapersInfo` (QML singleton, `WallpapersInfo::initialize(&app)` in `main.cpp`) is the per-file media cache: `~/.cache/kwal/wallpapers_info.json` (versioned array of entries; v1→v2 migration on load clears auto categories and reprocesses — manual categories/tags are preserved via the `*_manual` flags), `video_frames/<md5>.png` (ffmpeg first frame) and `thumbnails/large/`. Refresh jobs run on a QThreadPool (max 2) and per entry store: matugen source colors (only while the dots setting is on), automatic color categories computed from the image itself (Celebi top-8 → HCT classifier, capped at 5 by dominance), user tags, the P5 resize result, and the `animated` probe (`QImageReader::imageCount()` frame count, off-thread and cheap — ≤23 ms for a 34 MB GIF, 0–1 ms for WebP; `supportsAnimation()` is NOT usable for detection: the gif handler reports it as a format capability and answers true for single-frame GIFs, while the webp handler answers per file; videos are never animations; an up-to-date entry from an older index is filled by `fillMissingAnimatedProbe` without a full reprocess, which emits `entryChanged` once). `isAnimatedFor(path)` (`Q_INVOKABLE`) feeds the grid `isAnimated` role and the drawer, falling back to the gif/webp/avif/jxl extension rule while the entry is unprobed (`-1`) — a static GIF/WebP never pays the QMovie path. Videos are resized **on demand**: `AppController::generateVideoResizes(folder)` (the Settings "Generate resizes" button) runs `planResize()` for every video in the folder as a tracked batch (`resizing`/`resizeTotal`/`resizeCompleted`), encoding a cache copy `video_resizes/<md5>_<H>p<fps>.mp4` (x264 veryfast CRF 23, no audio) — only when a scale or fps reduction is actually needed — stored per entry in `resized`; there is **no auto-generation** on scan or settings change — but applying a video while `resizeEnabled` is on and no usable copy exists generates it for that single video first (`WallpapersInfo::ensureResizedCopy`, called by the apply job, mirrors the batch's entry semantics: completed plan stores/clears `resized`, probe/encode failure clears it and applies the original). `sweep()` (at startup, after `load()`, and after every scan) removes entries whose `file` no longer exists and the orphan files in `video_frames/` / `video_resizes/` not referenced by a surviving entry's `first_frame` / `resized` full path; it saves the JSON when anything changed and emits `purged()`, which `AppController` connects to `PlasmaApply::pruneDeadVideoUrls` (dead `VideoUrls` entries leave the desktop `appletsrc`; `thumbnails/large/` is deliberately not swept — small and self-regenerating).
- `WallpaperModel` (QAbstractListModel over the current folder: images + videos) + `FdoThumbnailProvider` (QQuickImageProvider `fdo_thumbnail`) feed the grid; video cells show the first frame (no provider bridge — the frame PNG is decoded directly) and play muted inline (`MediaPlayer`+`VideoOutput`, selected cell only); GIF/WebP animation is gated: the `isAnimated` role (the cached `WallpapersInfo` frame-count probe, extension fallback while unprobed) feeds the cell, and the `AnimatedImage` lives in a `Loader` that is active **only while the cell is the selected, visible one** (armed by a 250 ms delay mirroring the video gate) — every other cell and every scroll pass stays on the static first-frame thumbnail, and a single GIF never decodes frames repeatedly (QMovie caches all frames and decodes on the GUI thread; the old always-live `AnimatedImage` re-read and re-decoded the original file on every delegate recycle). APNG is deliberately out — Qt 6.12's PNG handler reports no animation, so an APNG is a still everywhere); frames are decoded at the cell's real size — `sourceSize` `Qt.size(min(cellWidth×DPR, 768), 0)` (the zero height makes Qt scale the cached frames keeping the aspect ratio, a fixed square would stretch non-square frames): `QMovie`'s `setScaledSize` is a decode **target**, not a cap (QImageReader scales at read; handlers without scaling support fall back to native decode + software transform — measured: the gif handler scales, the webp one upscales after native decode), so the old fixed 1280 px cap cached and upscaled more pixels than the 768 px cell ever showed (a 1600×898 `hex.gif`: 2.7 MB per frame, ×232 frames); the drawer sizes the same way from the panel's settled width (≤1024 px, fed only once the width settles — changing scaledSize re-reads every frame). Search filters by text over name/tags and by the 15 color-category chips (AND). Double-click on a cell opens `WallpaperDetailDrawer` — a non-overlay panel in the page's RowLayout, right of the grid, taking a configurable fraction of the content width while open (`detailPanelFraction`, currently 0.4 — pushing the grid aside, which falls back to a single full-width column — animated like the Folders sidebar; while open it follows the grid selection, so moving the highlight switches its content; closes via X, Escape, or a cleared selection): editable category/tag chips (wrapping `Flow`; manual overrides survive rescans; a reset button recalculates the automatic ones and clears the manual flag; an AI button (`tag-new`) adds AI tags through `AiTagger::tagWallpaper` (merged, non-destructive)), the palettes, and a Commands page with the custom-commands list (a `ListView` + `Kirigami.ListItemDragHandle` for drag reordering, enable switch, command text with a placeholder hint, delete). The matugen source colors (first dot selected by default, click to change the selection that feeds `%scolor%`/`%sc%`) are overlaid at the drawer media's bottom-left, like the grid's selected cell. All `ColorDot` swatches (source-color dots, the 15 category chips, the tool-page palette/picker swatches) are **mouse-operated only**: they stay out of the Tab chain (`activeFocusOnTab: false` where instantiated, never focusable in `ColorDot` itself) so the keyboard chain never walks or traps on them — the user asked explicitly for mouse selection after keyboard dot groups proved confusing. Accessibility is only informational (`Accessible.role: Button` + name); the clipboard `TextEdit` is `Accessible.ignored` (phantom editable field per dot).
- `PaletteExtractor` (owned by `AppController`, QThreadPool): Material You via the official `mcu` library (Celebi → `RankedSuggestions` → the nine M3 schemes in one pass, cached per wallpaper + dark mode so scheme switches answer instantly, 16 swatches each) or ImageMagick unique colors + accent; videos are extracted from the cached first frame. `src/colorcategory.{h,cpp}` holds the HCT (OKLCH, mcu `Hct`) classifier (15 matugen-style categories) shared by the category pipeline and the palettes.
- `AiTagger` (QML_ELEMENT, owned by `AppController`; `src/aitagger.{h,cpp}`): AI tag generation against an OpenAI-compatible **vision** chat API (a local `llama-server` with a vision model works). Settings persist in `[Wallpapers]` (`aiEndpoint`, `aiModel`, `aiSystemPrompt`, `aiFolder`); `fetchModels` GETs `<endpoint>/v1/models` (a bare host URL gets `/v1` appended) and the model combo lists **only models whose reported input modalities include `image`** (`parseModels` understands the llama.cpp `architecture.input_modalities` and OpenAI `capabilities.input_modalities` shapes; servers that report no modalities keep every model — legacy). `tagFolder(folder)` queues every image + video in a folder and `tagWallpaper(path)` tags a single one — sequential, one request at a time, `QNetworkAccessManager` with a 600 s transfer timeout (slow local models). Each request POSTs the user-editable system prompt (default built in) plus a multimodal user message (text part: file name + media type; `image_url` part: the wallpaper as a **1024 px-max JPEG, q85, built on the fly** — vision encoders resize to ~that range anyway, so the original 4K bytes buy nothing; videos send the cached first frame; an undecodable source falls back to the raw file with its real MIME type) to `<endpoint>/v1/chat/completions`. The image resolution, resize and JSON body building run in a nested `RequestJob` on the class's own `QThreadPool` so the GUI thread only posts the request and parses the small reply. The response is parsed by the pure helpers in `namespace aitagger` (`normalizeBase`, `buildUserMessage`, `buildUserContent`, `resizedJpeg`, `parseModels`, `parseTags` — JSON array inside arbitrary prose, comma/semicolon fallback, dedupe, defensive 10-tag cap; unit-tested in `tst_aitagger` with no network) and merged into the existing tags through `WallpapersInfo::mergeTags` (existing tags survive, duplicates dropped case-insensitively; sets `tagsManual` so AI tags survive rescans). Progress: `tagging`/`tagTotal`/`tagCompleted`; results: `wallpaperTagged(path, ok, message, tags)` and `taggingFinished(ok, failed)`.
- Tool tabs (Fastfetch, Starship, Ulauncher): a `QML_ELEMENT` controller each (`FastfetchController`, `StarshipController`, `UlauncherController`) backed by `src/tools/` (config read/write with `.bak` backup, Fastfetch logo tinting via ImageMagick — grayscale + `-tint` in a single pass, an animated GIF destination uses `-coalesce` and keeps every frame, delay and loop count, a still destination is the first frame; an animated **WebP → WebP** pass needs no `-coalesce` — verified on the user's 162-frame logo: the plain single pass emits 162 frames with `Iterations: 0` (loops forever), byte-identical to the `-coalesce -loop 0` variant, because ImageMagick's WebP writer re-encodes the whole animation itself; the pass runs on a `QThreadPool`, the preview coalesces per color change and the apply exposes `busy` for the spinner; the Current (config) and Selected previews play GIFs **and animated WebP** with `AnimatedImage` (both preview areas gate on an `isAnimated` suffix test, GIF + WebP, exactly like the grid/drawer; `AnimatedImage` accepts the controller's cache-busting `file://…?t=<rev>` URL — verified Ready/2 frames under offscreen), width-capped `sourceSize: Qt.size(1280, 0)` like the grid, `playing: page.visible` so the tab's animation pauses when hidden), while the Tinted preview stays a static `Image` by design (its content is mid-tint) —, Starship terminal-HTML preview — file-on-disk and live draft, pane-fit scaled via `previewScale` —, Ulauncher theme + live QML mockup). `UlauncherController` is owned by `AppController` (constructor with the app's own KConfig `[Ulauncher]` group) and shared by the tab and the Ulauncher settings page, so preview-mockup settings (window width, typed query, sample rows) are app-local and persist in `kwalrc`. Bundled templates are compiled in and copied to `~/.config/kwal/templates` at startup (`tools::installTemplates`); a tab appears only when its binary is on `PATH`. The three pages are created **lazily on first tab activation** (`Main.qml` `activateTab(id)`/`currentTabIndex()` — only `pageStack.initialPage` (WallpapersPage, index 0) exists at startup; each tool page is `createObject`+`push`ed once, then navigated by page identity via `pageStack.get()`), so their `WebEngineQuick` views and native resources only materialize when the user opens that tab. Their shared chrome — transparency-aware `pageBackground`, the page `background`, suppressed `globalToolBarStyle`, and the modal result dialog + `showResult()` — lives in `qml/ToolPage.qml` (a `Kirigami.Page` base with `app`/`resultTitle`); each page keeps its own typed `controller` property, its `Connections { onOperationResult → showResult }` (controller differs per page) and its `onVisibleChanged` refresh.
- Two windows: `Main` (tabs: Wallpapers, Fastfetch, Starship, Ulauncher) and a lazily-created `SettingsWindow` from the header menu. SettingsWindow pages: General, Wallpapers (matugen dots, color-category toggles, lockscreen mirror switch, and the video-resize group: an apply-the-scaled-copy switch, an editable target-height combo (720p/1080p/1440p/2160p presets + free entry) and an editable frame-rate combo (`current` = 0/keep source fps, 24/30/60 presets + free entry, `qml/FpsComboBox.qml` — also used by the transitions advanced group), and a per-video-folder picker with a "Generate resizes" button, a "Clear resizes cache" `edit-clear` button (`WallpapersInfo::clearAllResizes`, disabled while a batch runs) + progress bar; AI tagging group: endpoint input, model combo with a fetch button, system-prompt editor, folder combo with a `tag-new` icon button, a "Clear all tags" `edit-clear` button (`WallpapersInfo::clearAllTags`, disabled while tagging runs) + progress bar; both clear buttons report the result through the settings window's passive notification), Ulauncher (preview-mockup settings) and About are implemented; About is the standard `Kirigami.AboutPage` fed by the `AboutInfo` QML singleton (initialized in `main.cpp`, exposed via `setExternalSingletonInstance`), which parses the bundled `aboutdata.json` (typical KDE layout — edit that file to change name, version, description, homepage, license, copyright and authors) and the bundled `LICENSE.txt` (license sheet text) into a KAboutData-shaped `aboutData()` object; Fastfetch and Starship are placeholders.
- Wallpapers settings diagnostics (`qml/WallpapersSettingsPage.qml`): two `Kirigami.InlineMessage` warnings at the top of the page for the two failures nothing else surfaces. (1) Formats this Qt cannot decode: `AppController::unreadableWallpaperFormats()` feeds `wallpapermodel::unreadableFormats(QImageReader::supportedImageFormats(), WallpaperModel::imageExtensions())` — pure, unit-tested in `tst_appcontroller::testUnreadableFormats` (lowercased, accepted order, deduped, the jpeg handler's `jpe`/`jfif`/`jpg`/`jpeg` alias group counts as one codec; the qt6-base built-ins must never be reported) — and the page's `formatPackages` map names the Arch package per handler (`qt6-imageformats`, `qt6-svg`) that `installHint()` joins. Empty on a complete Qt, so the message never shows there. (2) Missing video wallpaper plugin: `AppController::videoWallpaperPluginInstalled()` (`PlasmaApply::rebornAvailable`, the real user/system Plasma wallpaper dirs); the message is visible only while `page.visible` **and** `app.videoFolders` (folders that actually hold videos, `recomputeVideoFolders`) is non-empty — re-evaluated on every page visit, so installing the plugin needs no restart, and the `&&` short-circuit keeps the probe off the disk when no folder has videos.
- Settings via KConfig (`kwalrc` → **`~/.config/kwalrc`**: `KConfig::SimpleConfig`, so the file sits directly in `$XDG_CONFIG_HOME`, NOT in `~/.config/kwal/`, which only holds the `templates/` installed at startup; `AppController::configFilePath()` reports the real path. The stray `~/.config/kwal/config.toml` on a dev machine is a leftover of the Python original — nothing in this rewrite reads or writes TOML config); identity: `OrganizationName "KDE"`, domain `kde.org`. Groups:
  - `[Wallpapers]`: `folders`, `currentFolderIndex`, `currentWallpaper`, `matugenDots` (show matugen source-color dots on the selected wallpaper; default = matugen availability), `colorCategories` (show the color-category chips in the wallpapers search; default **true** — the categories come from the image, not from matugen), `lockscreen` (mirror the applied wallpaper into `kscreenlockerrc` as well; default **false**), `resizeEnabled` (apply the scaled cache copy instead of the original video; default **false**; while on, the apply job uses the existing cache copy or generates it on demand for the single picked video before the switch — `WallpapersInfo::ensureResizedCopy`, blocking in the apply job, emitting `resizeCopyStarted`/`resizeCopyFinished` — a folder-wide batch is still explicit via the Settings "Generate resizes" button), `resizeHeight` (target height in px, default 1080, clamped 480–4320), `resizeFps` (0 = keep the source fps, clamped 0–240), `sourceColorSelections` (compact JSON object holding **only** the applied wallpaper's selected matugen dot index — single entry, rewritten on every dot click on it and on every apply; load drops entries of other wallpapers; empty/absent = the first dot applies), `aiEndpoint` (OpenAI-compatible API base URL for AI tagging; empty = disabled), `aiModel` (model id sent to the API), `aiSystemPrompt` (tag-generation system prompt; empty = built-in default), `aiFolder` (last folder tagged from the settings page). Matugen extraction (source colors → drawer dots only) runs while `matugenDots` is on.
  - `[Commands]`: `commands` — compact JSON array of `{"command": string, "enabled": bool}` (absent = empty); edited only through the drawer's Custom commands page (rows are drag-reorderable); the enabled commands are executed last when a wallpaper is applied. `themeMode` (`dark`/`light`, default `dark`) and `customColor` (hex, default empty) feed the `%mode%`/`%ccolor%` placeholders.
  - `[Transitions]`: `transitionEnabled` (default **false**), `transitionLayer` (`background`/`bottom`/`top`/`overlay`, default `bottom`), `transitionType` (preset: `grow` (default), `fade`, `wipe`, `wave`, `left`, `right`, `top`, `bottom`, `center`, `outer`, `simple`, `any`, `random`), `transitionAdvanced` (default **false** — while off the binary uses per-type presets and ignores the values below), `transitionDuration` (seconds, default 0.9), `transitionFps` (0 = uncapped, clamped 0–240), `transitionStep` (simple steps, clamped 1–255), `transitionAngle` (wipe/wave degrees; 0 = right→left, 90 = top→bottom, default 45), `transitionPos` (reference pos grammar: `center`, `random`, `x y` — fractions or pixels), `transitionInvertY` (default **false**), `transitionBezier` (default `.54,0,.34,.99`), `transitionWaveWidth`/`transitionWaveHeight` (default 20).
  - `[General]`: `windowWidth`/`windowHeight` — applied **at startup only** (window default 960×650, clamped to 700×400–3840×2160); no live resize. `transparency` — window background opacity. `transparencyLevel` — background opacity in percent (0–100, default 80, SpinBox step 5); only applied while `transparency` is on.
  - `[Ulauncher]`: `previewWindowWidth` (launcher width in the preview mockup, default 900, clamped 400–1200), `previewQuery` (text typed in the mockup input, default `fir`), `sampleRows` (list of `{icon, name, shortcut, selected}` maps shown in the mockup; empty falls back to the built-in samples — Firefox/Firefox/Alt+1 selected and Filelight/Filelight/Alt+2, query `fir`).
- QML: `qsTr()` for all user strings, `Kirigami.Units` for spacing/sizing, semantic `Kirigami.Theme` colors, Kirigami semantic components over raw Controls.
- Keyboard/focus chain: the Wallpapers grid is a **single Tab stop** (`GridView.activeFocusOnTab: true`; the `WallpaperItem`/`FolderRow` delegates are `activeFocusOnTab: false` so Tab never walks the items), the focused cell shows a highlight-color ring, click re-focuses the grid, and **Space opens the detail drawer** (ItemDelegate consumes Space itself, so the delegates carry explicit `Keys.onSpacePressed` handlers — same pattern in `FolderRow`). The folder sidebar `ListView` is the sidebar's single stop (arrow keys move the cursor, Enter/Space applies the folder under it). `ColorDot` is keyboard-operable (Enter/Space activate, ring when focused) but **Tab stops at its group, not at each dot**: `SourceColorDots` (grid cell + drawer) and the WallpapersPage category-swatch row are single Tab stops carrying an internal keyboard cursor (`activeFocusOnTab: true` on the row, `false` on the dots; Tab lands on the cursor dot, Left/Right move the cursor inside the group, Tab again leaves it); standalone dots (tool-page pickers) stay direct Tab stops. Escape (an `ApplicationShortcut` `Shortcut` active while the drawer or search is open) closes the drawer/search and calls `gridView.forceActiveFocus()`; closing search via the header toggle returns focus to the grid too. Header buttons live in the page header (tab bar is a focus scope; `menuButton` sits in `Main.qml`'s header row). SpinBoxes/DoubleSpinBoxes in the settings pages set `activeFocusOnTab: true` (they are editable controls but Kirigami styles leave them out of the Tab chain by default).
- Install (ECM): `install(TARGETS kwal kwal-transition RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR})` + desktop file installed as `org.kde.kwal.desktop` (matching the `org.kde.kwal` app id; `main.cpp` calls `setDesktopFileName("org.kde.kwal")` for window/StartupNotify matching) + hicolor icon. The QML module `org.kde.kwal` needs no install rules: `qt_add_qml_module` embeds its sources and qmldir in the binary's resources and `loadFromModule` resolves them from qrc (verified by running the staged binary). The version is canonical in `project(VERSION)`; configure `FATAL_ERROR`s if `aboutdata.json`'s `Version` diverges. The mcu GCC-16/abseil source fix lives in `cmake/mcu-gcc16.patch` (applied via FetchContent `PATCH_COMMAND`, and at configure time to a pristine `FETCHCONTENT_SOURCE_DIR_MCU` tree; `FETCHCONTENT_SOURCE_DIR_*` + `FETCHCONTENT_FULLY_DISCONNECTED=ON` configure without network).
